# UI Kit

[![tests](https://github.com/alpha-omega-corp/laravel/actions/workflows/tests.yml/badge.svg)](https://github.com/alpha-omega-corp/laravel/actions/workflows/tests.yml)

The shared UI kit for small-business sites built on Laravel: themed Blade components, the palettes and directions they are drawn in, the layouts that arrange them, and the Tailwind Plus reference library — installed into an application with `php artisan ui:kit`.

This README also catalogues every worked design the kit ships: **2,194 designed pages** — 485 designs across 40 kinds of business, each a direction, a palette and a layout for every page.

## Installation

Requires PHP 8.3+ and Laravel 13. The package is private, so add its repository to the application's `composer.json` first:

```json
"repositories": [
    { "type": "vcs", "url": "https://github.com/alpha-omega-corp/laravel.git" }
]
```

```bash
composer require alpha-omega-corp/ui-kit
```

The service provider is discovered automatically.

## Usage

Copy the themed kit — the `x-kit` components, `resources/css/kit.css`, `resources/css/themes.css` and `resources/css/fonts.json` — into the application, at the same paths it has in this package:

```bash
php artisan ui:kit
```

Copy one raw Tailwind Plus component by reference instead. It arrives in Tailwind's default palette and is the application's to re-theme:

```bash
php artisan ui:kit layout/cards/01-basic-card
```

Files the application already has are kept; pass `--force` to overwrite them.

A site picks its look on `<html>`:

```html
<html data-palette="sandstone" data-direction="hearth">
```

and draws its pages from the components:

```blade
<x-kit.site-header />
<x-kit.hero />
<x-kit.schedule />
<x-kit.site-footer />
```

## Development

The workbench is a showcase of the kit, served by Testbench with Vite beside it:

```bash
composer run setup   # composer install, npm install, npm run build
composer run dev     # testbench serve + vite
```

| Route | What it shows |
| --- | --- |
| `/ui-kit` | every themed component |
| `/layouts` | the layout and application-shell categories |
| `/framework/businesses/{business}/{design}/{page}` | one page of one design, with every axis above it |
| `/framework/sheet/{business}` | every design of a business, page by page |
| `/framework/site/{business}/{design}/{page}` | the page alone, as a built site draws it |

Checks:

```bash
composer run lint         # pint
composer run types:check  # phpstan
composer run test         # lint check, phpstan and pest
```

## How a design is made

A design settles four choices over markup that never changes:

- **Direction** — *what kind of place this is*: CSS over one DOM, `[data-direction]` in `resources/css/kit.css`. No component reads it.
- **Palette** — *what colours and faces*: `[data-palette]` in `resources/css/themes.css`.
- **Layout** — *how a page is arranged*: which regions it has and which components stand in each.
- **Arrangements** — optional variants of single components (`hero — cover`, `site-header — centred`, …).

A business (`.claude/skills/ui-kit/businesses/<name>.md`) lists its pages, the layouts each may take and the directions that suit it; `.claude/skills/ui-kit/designs/<name>.md` settles worked designs from those; `workbench/content/<name>.php` is a fictional business of that kind to draw them with.
