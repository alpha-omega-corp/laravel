# table

Records in rows compared column by column, with a title and an action over them: an admin list whose values are read across.

## Placement

- console.main — fits: across the column, scrolling sideways in its own box once its columns pass the width
- workspace.detail — fits: the chosen item's rows, scrolling in its own box
- * — never: nothing wide goes in a side column, a card or a 36rem task, and a site's prices are the menu or the catalogue, which a direction draws

## Limits

- columns — 6; advice 4 (cognitive-load, working-memory)
- rows — 12 (choice-overload)
- title — 48 characters (law-of-pragnanz)

## Behaviour

- Its first column names the row, in ink where the others are soft, so it holds what a reader looks for, a name or a number. (serial-position-effect, selective-attention)
- Every row has one cell per column in the columns' order, and an unknown value is a dash, since a missing cell shifts the rest of the row under the wrong heading. (law-of-uniform-connectedness, law-of-similarity)
- Its cells never wrap: a long value is shortened in the data, and the whole of it is the record's own screen. (cognitive-load)
- Past four columns it scrolls sideways on a phone, so the columns a reader needs first come first. (serial-position-effect, pareto-principle)
- Past twelve rows it is paged, with pagination straight under it. (choice-overload)
- It is for comparing records: one record's facts are a description list, and a list to choose one item from is a stacked-list. (mental-model)
